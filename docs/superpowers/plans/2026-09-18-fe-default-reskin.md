# fe-default Re-skin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move the `fe-default` FE adapter from Tailwind v3.4 with an ad-hoc token vocabulary to Tailwind v4 with a standard semantic token layer, a terracotta default ramp, and a `crimson` preset.

**Architecture:** Styling lives almost entirely in static template files under `generator/templates/fe-default/`, which the scaffold copies verbatim — a measured census found ~200 token-bearing classes there and exactly 4 across the adapter and all of `src/fe`. The migration therefore edits templates and one adapter function, not the emitters. Tailwind's `@config` directive bridges the old JS config through the first three tasks so that every task leaves a working, buildable app; the bridge is removed once the new class vocabulary is in place.

**Tech Stack:** Tailwind CSS v4 (`@tailwindcss/postcss`), CRA 5.0.1 + CRACO 7.1.0, React 19, TypeScript, PostCSS 8.

**Spec:** `docs/superpowers/specs/2026-09-18-fe-default-reskin-design.md`

## Global Constraints

- **Tailwind v4 syntax is binding.** `@import "tailwindcss";` never `@tailwind base/components/utilities`. `@theme inline` with `var()` references, never literal values. `@custom-variant dark`, never `darkMode: 'class'`. `bg-(--x)` parens, never `bg-[--x]`. Trailing `!` important, never leading. `@utility`, never `@layer components`. `outline-hidden`, never `outline-none`.
- **No organisation name anywhere.** The preset is `crimson`. No organisation name may appear in a preset name, file name, identifier, or in any comment in generated output.
- **Components never reference brand primitives.** No `bg-primary-600`, `text-primary-700` in a component; the semantic layer only (`bg-primary`, `text-primary-foreground`, `bg-primary-hover`). Task 9 enforces this.
- **No arbitrary Tailwind values** (`p-[13px]`, `bg-[#DC2626]`) in any `fe-default` template or golden tree. Task 9 enforces this.
- **Zero new runtime dependencies.** The only dependency changes permitted are the Tailwind toolchain ones in Task 1.
- **Determinism.** Every generated byte must come from the FEIR plus static templates. No clock, no random, no absolute paths.
- **Browser floor is accepted:** Safari 16.4+, Chrome 111+, Firefox 128+.
- **Golden is never recorded blind.** Read the diff, state what changed and why, then `--update`.

- [ ] **Step 3: Rewrite `theme()` and `renderTokensCss()`**

```js
/**
 * @param {object} tokens ui.theme.tokens (override).
 * @param {boolean} darkMode emit blok .dark juga.
 * @param {string} [presetName] ui.theme.name -> pilih ramp brand.
 */
export function theme(tokens = {}, darkMode = false, presetName = undefined) {
  const { ramp } = rampFor(presetName);
  const root = { ...STATIC_PRIMITIVES, ...ramp, ...semanticAliasesLight(tokens) };
  if (!darkMode) return { ':root': root };
  return { ':root': root, '.dark': semanticAliasesDark(tokens) };
}

export function renderTokensCss(tokens = {}, darkMode = false, presetName = undefined) {
  const blocks = theme(tokens, darkMode, presetName);
  return Object.entries(blocks)
    .map(([sel, vars]) => `${sel}{\n${Object.entries(vars).map(([k, v]) => `  ${k}:${v};`).join('\n')}\n}\n`)
    .join('');
}
```

```js
  {
    name: 'FE @theme inline: var() references only (dark-mode trap)',
    run: () => {
      // Nilai literal di @theme diresolusi Tailwind saat BUILD, jadi override .dark
      // tidak pernah sampai ke utility: mode gelap mati tanpa error, build hijau,
      // kelas ada. Satu-satunya cara menangkapnya adalah memeriksa bloknya.
      const roots = [
        path.join(root, 'templates', 'fe-default', 'src', 'gen', 'app.css'),
        ...['fe-default-full', 'fe-default-dashboard', 'fe-default-mfe']
          .map((c) => path.join(root, 'golden', 'fe', c, 'src', 'gen', 'app.css')),
      ];
      const problems = [];
      for (const file of roots) {
        if (!fs.existsSync(file)) { problems.push(`${path.relative(root, file)}: tidak ada`); continue; }
        const css = fs.readFileSync(file, 'utf8');
        const m = css.match(/@theme inline\s*\{([\s\S]*?)\n\}/);
        if (!m) { problems.push(`${path.relative(root, file)}: tidak ada blok @theme inline`); continue; }
        for (const line of m[1].split('\n')) {
          if (!/:\s*[^;]*;/.test(line)) continue;      // bukan deklarasi
          if (/^\s*(?:\/\*|\*)/.test(line)) continue;  // komentar
          // Hanya skala tipe, font-mono dan radius-full yang SAH berupa literal -
          // ketiganya tidak berubah antara terang dan gelap, jadi tidak ada override
          // yang bisa gagal sampai. Sisanya wajib var().
          if (/--text-|--font-mono|--radius-full/.test(line)) continue;
          if (!/var\(/.test(line)) problems.push(`${path.relative(root, file)}: nilai literal -> ${line.trim()}`);
        }
      }
      return problems.length ? problems.join('\n') : '@theme inline: semua entri warna memakai var()';
    },
    ok: out => /^@theme inline: semua/.test(out),
    summary: out => /^@theme inline: semua/.test(out) ? '4 file OK' : out.split('\n').length + ' masalah',
  },
```

## Notes for the executor

- **Never record golden without reading the diff.** Several tasks produce diffs spanning most of 216 files. Sample them by category and confirm each category is an intended change. `--update` on an unread diff makes the snapshot worthless.
- **Always clear both FEIR caches before a hand-run scaffold.** `rm -rf ../.feir .feir` from `generator/`. The cache silently serves the previous spec, and this has already caused one wrong conclusion in this repo.
- **A green build does not mean Tailwind ran.** CRACO 7.1.0 with postcss-loader 6.x can drop the plugin silently. Check that the emitted CSS is populated, not just that the build exited 0.
- **If Task 1 cannot build, stop.** The spec says the design is void in that case, not that it should be worked around.
